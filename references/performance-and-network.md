# 性能、网络与 CDN 优化

## 先建立基线

固定浏览器、窗口尺寸、缓存状态、登录状态、网络条件和操作脚本，至少记录：

- 导航到首屏可交互的时间。
- LCP、CLS、长任务和主要脚本执行耗时。
- 关键 API 的 DNS/TCP/TLS/TTFB/下载时间。
- 图片/视频请求数量、失败率、重复请求和缓存命中。
- 信息流首批、后续批次和滚动触发的完成时间。

同一场景重复多次并报告中位数和异常值，不用一次“感觉快了”作结论。

## 连接和请求

- `preconnect` 只用于稳定且确实会访问的少量 origin，避免为测速、预连接和页面自身请求争抢首屏连接。
- 请求优先级要服从页面业务：首屏数据和首屏资源优先，辅助统计和非可见内容降级。
- 不要无条件给所有 fetch 加 `high`，也不要用短超时抢断仍在传输的有效响应。
- 重试必须有总次数、退避、取消信号和幂等判断；不要让一次失败引发并发风暴。
- 只改写已确认格式和主机的 URL，保留原始地址用于单资源回退。

## 图片和视频

- 通过原生尺寸、`loading`、`fetchPriority`、IntersectionObserver 和有限窗口实现按需预加载。
- 预加载“两行”必须有距离、数量和滚动预算上限，不能把整个信息流改成 eager。
- 视频预览不应被普通封面预加载逻辑改写；不改变清晰度、预览交互或站点播放器状态。
- 属性 patch 要避免重复设置同一值；失败回退不能在 error 事件中无限切换节点。

## CDN 节点选择

测速对象必须代表真实业务资源，而不是只测一个 favicon。按国内/境外或服务端明确地域选择候选节点时，记录来源、时间、状态和样本；缓存 TTL 要短且带 region/key 版本。

节点切换应满足：

1. 只对允许改写的主机和路径生效。
2. 保留原 URL、查询参数、签名和 referer 语义。
3. 具体资源失败时只回退该资源，不重写整个页面。
4. 连续失败才切节点，并有冷却时间。
5. 无法确认地域或签名完整性时保留站点原地址。

不要把“替换 host”当作通用 CDN 优化；签名 URL、MCDN、视频播放地址和图片对象的可替换性可能不同。

## 布局稳定

性能优化不能通过持续读写布局制造 CLS。批量读取几何信息后一次写入；避免在每个 mutation 中同步强制回流。对站点会动态重绘的卡片，优先使用容器级 childList 监听和稳定的 data 标记，不观察卡片 `class/style` 形成反馈。
