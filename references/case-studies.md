# 案例：首页信息流频闪

## 用户症状

首页第三排开始错位；鼠标悬停卡片时页面上下抽搐，后续版本进一步出现频闪。用户要求只优化加载速度和 CDN，不改变预览内容，也不重新安装或修改油猴。

## 证据链

实际页面观察到：

- 同一 CSS Grid 逻辑行混用 `margin-top: 0px/24px/40px`。
- B 站悬停预览会改变卡片或轮播内部的 `class/style`，并触发自身重绘。
- 对卡片或整棵子树的 class/style 观察会产生高频回调。
- 旧修复用 class 和 inline style 写回布局；B 站重绘移除这些状态后，脚本再次修复，形成反馈回路。
- `ResizeObserver` 也会把由预览和图片解码引起的尺寸变化重新送回布局修复。

## 排查和修复

用两个对照页面采样：

1. 旧版本：4 秒内出现卡片几何变化。
2. 隔离本地版本：移除卡片级属性监听和 `ResizeObserver` 后，悬停 5 秒 `geometryChanges: 0`。

最终策略：

- 只监听信息流容器直接子节点的新增/删除。
- 用 `data-bk-feed-layout` 和 `data-bk-feed-layout-margin` 标记，避免站点重写 class/style 时丢失状态。
- 用 CSS 规则统一间距，不在每次预览重绘时同步读取和写入布局。
- 保留原始 margin 的 WeakMap，避免读到脚本自己覆盖后的值。

## 可复用教训

- “监听更多变化”不等于“修复更可靠”；对框架控制的 DOM，监听越宽越容易产生反馈。
- 先统计 mutation、几何变化和请求，再决定观察范围。
- 用户说“频闪”时必须测量元素 top/left/height 的变化，截图只作为补充。
- 预览、图片解码、轮播动画和布局修复要分开；不能把预览内部 DOM 变化当成信息流新增。
- 临时 DevTools 注入可验证本地代码，但刷新后会恢复油猴安装版本；必须分别报告临时注入、文件修改和实际写入三种状态。
